# 分组单调样条的可逆校准与梯度

模型分组校准配方使用有理二次样条，组参数和探针行来自合成量程。 数据为本地合成。

- `data/capture.json` 保存采集原始内容。records 是交换记录，tensors 字段分开描述名称、类型、形状和值。整数索引从零开始，未指定闭合的区间均为左闭右开。
- `data/capacity.json` 保存制造端的容量、规模或分片条件。大尺寸是接口需考虑的使用规模。工作区计入新分配的解包、转换、归约、版本暂存及交接缓冲。调用方已有只读输入和已消费的输出不计入工作区，额外物化副本计入。

## 交换约定

宽高为输入、输出边界之间的正比例，分别和为一。每组提供区间 `[x0,x1,y0,y1]` 与各结点正导数，使各分箱形成同一连续、严格增函数；各参数轴顺序见 `groups`。允许区间外线性尾部，斜率取对应端导数，同一端点值相连。箱边采用左闭右开，最后一个箱包含右边界；当参照 float64 不能可靠地区分两侧，必须能以坐标及往返误差复核，依精确结点判定，不能凭梯度送到另一箱。验收的绝对往返误差为 2e-9，对数雅可比误差为 5e-8。
箱内比率 y-y_left 与箱高之比按常见单调有理二阶 Hermite 插值定义。令 u 为归一横坐标、s 为箱高除箱宽、d0 和 d1 为端导数。其比率为 [s*u*u + d0*u*(1−u)]/[s + (d1+d0−2*s)*u*(1−u)]。前向对数雅可比为 log(dy/dx)，逆向为 log(dx/dy)。网络训练对宽高已归一化的参数沿各自和为一的切空间比较梯度，返回分量和为零的代表，端导数独立，量程端点固定。校准链每级先按新通道读哪个旧通道的方式置换，然后按级配置指定的参数组处理。逆向沿反方向恢复。每个绕过位随原通道身份移动。各级每组端点可不同。损失可同时对数值和对数雅可比施加权重，输入与参数梯度核对绝对容差 2e-6。

`chain_rows` 每行依次提供请求 ID、链、方向、通道值和观测掩码，掩码 1 表示参与变换。`chain_batches` 依次给出同批输入和要求使用的参数版；新批可引用 `bad_update` 中提交的版本。`chain_upstream` 提供回传请求 ID、按交付通道排列的各值梯度及总对数雅可比梯度。`replay_chain_upstream` 表示第二批请求后重发这组回传，所引用的批次下标从零开始。

## 读取资料

使用 Python 3.11。首次创建本地环境时安装锁定依赖。只读查看显示原始字段和张量尺寸。

```sh
python -m pip install -r requirements.txt
python caseio.py data/capture.json
python -m unittest discover -s tests -v
```

现有检查核对采集格式和所附数据的结构。

## 可逆校准实现

`rqs/` 提供可在训练与回放中调用的成组可逆有理二次样条算子：

- `rqs/splines.py`：单组 RQS。按正宽、正高、导数下界、归一化与连续性
  接纳参数；正向/逆向共用同一结点判定（左闭右开、末箱含右端点）与线性
  尾部口径；返回值、对数绝对雅可比、分箱编码、贴边标志与残差。正/逆向
  VJP 为解析梯度，宽高沿和为一的切空间返回分量和为零的代表，端导数
  独立、量程端点固定。
- `rqs/registry.py`：组身份的多版本注册表。坏提交（含破坏单调的负导数）
  登记为无效版本并隔离，历史版本保留；未知版本单独隔离。
- `rqs/chains.py`：多级校准链。每级先按“新通道读哪个旧通道”置换再按
  组处理，掩码随通道身份移动，无观测位以 NaN 绕过且不贡献密度，总对数
  雅可比只累计有效通道与实际走过的级；逆向反向恢复坐标、组身份与掩码。
  反向回放按同一前向承诺（组版本、分箱编码逐点）核对，偏离即抛
  `CommitmentMismatch`，不静默换侧密度。无效组只落在绕过位的行仍可评分，
  命中观测位的行给不可用原因且受影响输出为 NaN。
- `rqs/receipts.py`：紧凑收据，逐点只存 int16 分箱编码、贴边标志、残差
  与版本承诺，不存整组参数或搜索表；超驻留预算的分片压缩外溢，回查透明。
- `rqs/app.py` / `rqs/cli.py`：把采集资料接到工作流，落盘正反变换记录、
  输入与参数梯度、不可用原因、分箱归属回查和容量自检。

```sh
python -m rqs.cli data/capture.json data/capacity.json -o out
```

容量口径：分片工作区按 `capacity.json` 的 `partition_rows` 与
`peak_scratch_bytes` 约束，收据单块受 `max_receipt_bytes` 约束，累计收据
超出驻留预算即外溢；调用方只读输入与已消费输出不计入工作区。
